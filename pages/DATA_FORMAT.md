# Формат данных словаря (lv-data*.json)

Контракт для файлов данных, которые читает `lv-edvibe-cheatsheet.html`. **Источник правды по структуре —
`lv-data.schema.json`.** Этот документ объясняет
правила, которые схемой не выразить (порядок загрузки, слияние категорий, стиль контента).

---

## 1. Как файлы загружаются

```
lv-data.json  →  lv-data-1.json  →  lv-data-2.json  →  …
```

| Правило                                                                        | Последствие нарушения                                                                      |
|--------------------------------------------------------------------------------|--------------------------------------------------------------------------------------------|
| `lv-data.json` обязателен и грузится первым                                    | Без него страница показывает ошибку «Файлы данных не найдены»                              |
| Нумерованные файлы идут **без пропусков** начиная с `1`                        | Загрузка обрывается на первом отсутствующем номере; все следующие файлы молча игнорируются |
| Каждый файл — валидный JSON в кодировке UTF-8                                  | Файл пропускается (выглядит как пустая категория)                                          |
| `lv-data.json` содержит **полную** структуру, нумерованные — только дополнения | —                                                                                          |

**Пример:** есть `lv-data-1.json` и `lv-data-3.json`, но нет `-2` → `-3` не загрузится.

### Одна партия пополнения = один файл

Каждое пополнение словаря оформляется **новым файлом** `lv-data-N.json`, где `N` — следующий
свободный номер. Существующие файлы не редактируются, если это не исправление ошибки.
Следующий номер определяется по факту наличия файлов в `pages/`, а не по памяти:
проверяйте, что все номера `1..N-1` существуют.

---

## 2. Слияние категорий

- Категории с одинаковым `name` (точное совпадение, с учётом регистра) **объединяются**:
  `items` дописываются в конец в порядке файлов.
- Категория с другим `name` создаёт **новую вкладку**, даже если тематически похожа.
- `card_title` и `description` берутся из первого файла, где они заданы.
- `last_updated` и `module_info` перезаписываются **последним** файлом, где они есть.

Следствие: опечатка в `name` (`"Професси"` вместо `"Профессии"`) = дубликат вкладки.
Не добавляйте необязательные поля, если их уже задал основной файл, — они всё равно не применятся.

---

## 3. Структура

### Корень

| Поле           | Тип                 | Обяз.  | Назначение                                              |
|----------------|---------------------|--------|---------------------------------------------------------|
| `last_updated` | string `DD.MM.YYYY` | нет    | Дата в шапке страницы                                   |
| `module_info`  | string              | нет    | Подпись в шапке, напр. «По состоянию на конец блока №2» |
| `categories`   | array               | **да** | Список категорий                                        |

### Категория

| Поле          | Тип                          | Обяз.                      | Назначение                                     |
|---------------|------------------------------|----------------------------|------------------------------------------------|
| `name`        | string                       | **да**                     | Имя вкладки; **ключ слияния**                  |
| `icon`        | string                       | **да**                     | Имя иконки Material Icons (латиницей) — см. §4 |
| `type`        | `"standard"` \| `"antonyms"` | нет (по умолч. `standard`) | `antonyms` → таблица пар                       |
| `card_title`  | string                       | нет                        | Заголовок карточки (по умолч. = `name`)        |
| `description` | string                       | нет                        | Подпись под заголовком                         |
| `items`       | array                        | **да**                     | Слова; форма зависит от `type`                 |

### Item, `type: "standard"`

| Поле          | Тип    | Обяз.  | Назначение                                 |
|---------------|--------|--------|--------------------------------------------|
| `icon`        | string | **да** | Emoji (👨‍👧, 🚀). **Не** имя Material Icons  |
| `word`        | string | **да** | Слово/фраза **по-латышски**                |
| `translation` | string | **да** | Перевод **по-русски**                      |
| `example`     | string | нет    | Короткое предложение на латышском (тултип) |

### Item, `type: "antonyms"`

Плоская пара в одном объекте (не массив и не вложенные объекты):

| Поле            | Обяз.  | Назначение                  |
|-----------------|--------|-----------------------------|
| `word_a`        | **да** | Латышское слово A           |
| `translation_a` | **да** | Перевод A                   |
| `example_a`     | нет    | Пример с A                  |
| `icon_a`        | нет    | Emoji для A                 |
| `word_b`        | **да** | Латышское слово B (антоним) |
| `translation_b` | **да** | Перевод B                   |
| `example_b`     | нет    | Пример с B                  |
| `icon_b`        | нет    | Emoji для B                 |

## 4. Реестр известных категорий

Используйте **точные** `name`/`icon` из таблицы, чтобы дописывать в существующую вкладку.
Новую категорию добавляйте **только** для новой темы; новый `icon` выбирайте из
[Material Icons](https://fonts.google.com/icons) и проверяйте, что имя в снапшоте шрифта есть.

| `name`                | `icon`           | `card_title`                                         |
|-----------------------|------------------|------------------------------------------------------|
| `Антонимы`            | `compare_arrows` | `Прилагательные - Пары Антонимов` (type: `antonyms`) |
| `Семья и люди`        | `group`          | —                                                    |
| `Профессии`           | `work`           | `Профессии и деятельность`                           |
| `Дом и быт`           | `home`           | `Дом, интерьер и предметы`                           |
| `Город и места`       | `location_city`  | —                                                    |
| `Животные и природа`  | `pets`           | `Природа и животные`                                 |
| `Время и даты`        | `schedule`       | `Время, дни и времена года`                          |
| `Еда и напитки`       | `restaurant`     | `Еда, напитки и лакомства`                           |
| `Глаголы`             | `directions_run` | `Глаголы и действия`                                 |
| `Местоимения и фразы` | `chat`           | `Местоимения, вопросы и полезные фразы`              |

Когда добавляете сюда новую категорию — обновляйте и эту таблицу, и `known_categories`
в `lv-data.schema.json` (второе используется валидатором).

### Куда писать типовые пополнения

| Что добавляете                           | Категория             |
|------------------------------------------|-----------------------|
| Существительное-предмет                  | `Дом и быт`           |
| Место/учреждение                         | `Город и места`       |
| Профессия/деятель                        | `Профессии`           |
| Родственник/характеристика человека      | `Семья и люди`        |
| Зверь/птица/природа                      | `Животные и природа`  |
| День, месяц, время года, наречие времени | `Время и даты`        |
| Еда/напиток                              | `Еда и напитки`       |
| Глагол/действие                          | `Глаголы`             |
| Вопрос, частица, число, готовая фраза    | `Местоимения и фразы` |
| Пара противоположных прилагательных      | `Антонимы`            |

## 5. Правила контента

1. **Языки**: `word*` — только латышский (диакритика `ā č ē ģ ī ķ ļ ņ š ū ž` обязательна);
   `translation*` — только русский. Смешение — ошибка.
2. **Пример**: 3–7 слов, простое предложение на латышском, содержит само слово (допустимо в другой форме — `Vilciens`,
   но не другое слово).
3. **Иконка item** — один emoji, по смыслу слова. Не имя Material Icons.
4. **Без HTML** в строках: всё выводится через `escapeHtml`, теги попадут в текст как есть.
5. **Без дублей**: прежде чем добавлять слово, поищите его (в т.ч. с учётом окончаний) по всем `lv-data*.json`.
6. **`translation`** — одна строка; варианты через ` / ` (`новый / молодой`), не через запятую-перечисление вразнобой.
7. Не переименовывайте существующие `name` — это ломает слияние.
8. Запятые внутри строк экранируйте так, как требует JSON; никаких комментариев (`//`) и висячих запятых.

## 6. Частые ошибки (встречались в реальных файлах)

- ❌ Имя иконки Material Icons в поле `icon` у item (например `"icon": "schedule"` вместо emoji) → в таблице появится
  текст `schedule`.
- ❌ Несуществующее имя иконки у **категории** (`"gene"`, `"shopping"` вместо реального из набора) → вкладка без иконки.
  Проверяйте имя в [Material Icons](https://fonts.google.com/icons).
- ❌ `"Atкārtojiet"` — кириллическая `к` внутри латышского слова. Ловится поиском `[а-яА-Я]` в полях `word*`.
- ❌ `"iela ir garša"` (должно быть `gara`), `"putni dzēd"` (`dzied`), `"Sieviete pēk puķes"` (`Sieviete plūc puķes`) —
  примеры без вычитки.
- ❌ Антонимы добавлены как обычные слова (`type: standard`) → не попадут в таблицу пар.
- ❌ Новый файл `lv-data-3.json` при отсутствии `lv-data-2.json` → не загрузится.
- ❌ Категория `"Города"` вместо `"Город и места"` → отдельная дублирующая вкладка.

## 7. Проверка перед коммитом

```powershell
# дубликаты, битая нумерация, кириллица, разнобой иконок — БЕЗ интернета
node check-vocab.mjs

# структура по схеме (исключаем сам файл схемы из маски)
npx.cmd --yes ajv-cli@5 validate -s lv-data.schema.json -d "lv-data.json" -d "lv-data-*.json" --strict=false
```

Не использовать маску `lv-data*.json`: она захватывает `lv-data.schema.json`.
Использовать `npx.cmd` (на Windows `npx.ps1` может быть заблокирован ExecutionPolicy).

`check-vocab.mjs` печатает:

- `✗ ОШИБКИ СТРУКТУРЫ` — пропуск в нумерации (файлы после дыры не загрузятся), битый JSON;
- `✗ ТОЧНЫЕ ДУБЛИКАТЫ` — одно слово в разных файлах/категориях (код возврата 1);
- `? ВОЗМОЖНЫЕ ДУБЛИКАТЫ` — совпала основа слова (`siers`/`siera`); смотреть глазами,
  разные падежи одного слова дубликатом не являются;
- `? РАЗНЫЕ ИКОНКИ КАТЕГОРИИ` — у вкладки в разных файлах разные `icon`.

Код возврата `1` при ошибках — можно вешать в pre-commit.

### Git pre-commit (уже установлен)

Хук `.git/hooks/pre-commit` запускает `check-vocab.mjs`, **только** если в коммит попадают
`lv-data*.json`; обычные коммиты проходят без задержки. При найденных ошибках коммит отменяется.

```powershell
# переустановить (например, на новой машине или после клонирования)
node check-vocab.mjs --install-hook

# разово обойти проверку
git commit --no-verify
```

Хуки не попадают в git — после клонирования репозитория запустите `--install-hook` один раз.
Сам скрипт хука лежит под версионным контролем: `check-vocab-hook.sh`.

Чек-лист:

- [ ] Файлы валидны как JSON, нумерация непрерывна
- [ ] Все `name` совпадают с реестром §4
- [ ] У каждого item есть `icon`, `word`, `translation`
- [ ] Никаких латинских имён иконок в поле `icon` item и кириллицы в `word`
- [ ] Слова не дублируются между файлами
